# コード内コメントの抽出

日本語で書かれたコメント行だけを取り出すための検索。ソースの全行を読むと費用が対象外の量になるため、読む前に絞る。**完全な抽出は目的ではない**。取りこぼしのある絞り込みだと分かったうえで使う。

## コマンド

```bash
rg -n --hidden -g '!.git' -g '!*.md' -g '!*.mdx' -g '!*.rst' -g '!*.adoc' \
  '(^\s*(//|/\*|\*|#|--|;|%|<!--|!|\(\*|\{-|\|#|=begin)|\s(//|/\*|#|--|;|%|<!--))(?-u:.)*[\p{Hiragana}\p{Katakana}\p{Han}]' \
  .
```

## 構造

| 部分 | 役割 |
|---|---|
| `^\s*(...)` | 行がまるごとコメントの場合。行頭にだけ `!`(Fortran) `(*`(OCaml) `{-`(Haskell) `\|#`(Lisp) `=begin`(Ruby) を許す |
| `\s(...)` | コード行の末尾に付くコメント。記号を絞るのは、`!` を許すと `a !== b` が、`(*` を許すと式が誤ヒットするため |
| `(?-u:.)*` | UTF-8 として不正なバイトが日本語より手前にある行でも `.` が越えられるようにする |
| `[\p{Hiragana}\p{Katakana}\p{Han}]` | 日本語の判定 |

**行末コメントを落とすと取りこぼしの過半を失う**（18言語のコーパスで測定した際、取りこぼし21行のうち11行が行末コメントだった）。行頭だけに絞った版は再現率 24/45、この版は 39/45。

**文字コードの範囲で書かない。** `[ぁ-んァ-ヶ一-龠]` のような書き方は、`一-龠` が U+9FA0 止まりで CJK 統合漢字（U+9FFF まで）の末尾が切れ、半角カタカナ・`々`・`〆`・追加漢字面・`ヷヸヹヺ` も落とす。文字種プロパティならこれらをすべて拾う。

**末尾のパス `.` を省かない。** `rg` はパス引数がないと標準入力を読みに行き、閉じないパイプを待って停止する。

ドキュメントの拡張子を外すのは、`#` が見出し、`*` が箇条書きと衝突して大量に誤ヒットするため。それらは別途ドキュメントとして検査済みでもある。

## 言語に合わせた調整

記号の集合はリポジトリで実際に使われている言語に合わせて足してよい。ただし**記号を増やすほど誤ヒットも増える**ので、使っていない言語の記号は入れない。

`"`（Vim script、Visual Basic）は既定で外している。行頭 `"` を許すと JSON・文字列の配列・複数行文字列リテラルが大量に当たるため。これらの言語が対象なら、行頭側の集合にだけ `|"` を足す。

## 取りこぼすもの

**ブロックコメントの内部行**が最大の取りこぼし。記号のある行と日本語の行が別なので、行単位の一致では状態を持てず原理的に取れない。

```python
def f():
    """
    docstring の本文（この行は取れない）
    """
```

```c
/*
   記号のない内部行（この行は取れない）
*/
```

Ruby の `=begin`/`=end`、HTML の `<!-- -->`、Haskell の `{- -}`、Lisp の `#| |#` も同じ。**Python の docstring は日本語の説明を書く標準の場所なので、Python が主体のリポジトリでは影響が大きい**。日本語が記号と同じ行にある場合（`"""日本語の説明"""`）は拾える。

行コメント（`//` `#` 等）には該当しない。各行に記号が必要で、記号のない継続行は構文エラーになるため。

その他:

- Vim script と Visual Basic の `"` コメント（上記のトレードオフで意図的に除外）
- Fortran の行末 `!` コメント（`!=` との衝突を避けるため行末側から除外）
- Shift_JIS 等、UTF-8 と UTF-16 以外のエンコーディングのファイル
- 長音符と約物だけで構成される行（`ーーー`、`、。「」`）

## 誤って拾うもの

CSS の ID セレクタ（`#見出し {`）、`.txt` の箇条書き（`* 項目`）、シェルの長オプション（`--data "名前=太郎"`）、コメント記号を含む文字列リテラル（`"notify --to 宛先 # 宛先は必須"`）。いずれも1行読めば棄却できるので、取りこぼしより安い。

日本語を含むだけの文字列リテラル（`const msg = "配信の失敗"`）は拾わない。空白に続くコメント記号が要るため、URL（`https://example.com/ja/ガイド`）も拾わない。

`\p{Han}` は中国語も拾う。中国語のコメントが混在するリポジトリでは、これだけで日本語と判定できない。

## 言語別のパーサーを使わない理由

依存が増えるうえ、コメントを正確に切り出せても**読む量は変わらない**。費用を決めているのは走査ではなく、絞り込んだ後に読んで判断する量なので、抽出精度を上げても主因に効かない。
